## 1. Вступление и организация курса

### Дизайн и код идут парой

Курс идёт в связке с парой по дизайну. Там разбирают, **как макет выглядит и что чувствует пользователь**. Здесь — **как макет превращается в живую страницу в браузере**.

> Дизайнер, который понимает код, экономит недели переписки с разработчиком — и рисует то, что реально можно собрать.

Это не курс программирования. Здесь не будет алгоритмов, переменных и математики. HTML — это разметка: вы объясняете браузеру, чем является каждый кусок текста.

## 2. Откуда взялся веб

### Интернет и веб — это не одно и то же

**Интернет** — это инфраструктура: провода, серверы, протоколы. Появился в конце 60-х.
**Веб** — это страницы, которые живут поверх интернета. Появился в 90-х.

Можно пользоваться интернетом без веба: почта, мессенджеры, торренты — это интернет, но не веб.

### Таймлайн

| Год | Событие | Что произошло |
|---|---|---|
| **1969** | ARPANET | В США соединяют первые компьютеры в сеть |
| **1989** | Идея | Тим Бернерс-Ли в ЦЕРНе предлагает систему связанных документов для учёных |
| **1990** | Первый браузер | WorldWideWeb — он же первый редактор страниц, написан самим Бернерсом-Ли |
| **1991** | Первый сайт | `info.cern.ch` — страница о том, что такое веб и как сделать свою |
| **1993** | Mosaic | Первый массовый **графический** браузер: картинки прямо в тексте |

Обратите внимание: веб придумали, чтобы физики могли ссылаться на работы друг друга. Отсюда весь «научный» набор тегов, который мы разберём сегодня — заголовки, абзацы, списки, цитаты.

### Три вещи, на которых стоит веб

Придуманы больше 30 лет назад и работают до сих пор:

| | | |
|---|---|---|
| **URL** | Адрес | Уникальный адрес документа. То, что вы вбиваете в адресную строку |
| **HTTP** | Доставка | Протокол: как браузер просит страницу у сервера и получает ответ |
| **HTML** | Разметка | Язык, которым описано содержимое страницы. Наша тема |

```
https://hse.ru  →  запрос по HTTP  →  HTML-страница в браузере
```

### Mosaic и войны браузеров

До Mosaic веб был текстом в командной строке. После — стал визуальной средой. Именно с 1993 года имеет смысл говорить о **дизайне** сайтов.

| Год | Браузер | |
|---|---|---|
| 1994 | Netscape Navigator | Первый коммерческий хит, задал моду на новые теги |
| 1995 | Internet Explorer | Идёт в комплекте с Windows, быстро занимает рынок |
| 1995 | Opera | Норвежский браузер, много идей, которые потом взяли все |
| 2004 | Mozilla Firefox | Наследник Netscape, возвращает конкуренцию и стандарты |
| 2008 | Google Chrome | Быстрый движок, частые обновления. Сегодня — стандарт де-факто |

### Почему это важно дизайнеру

Конкуренция браузеров означала, что каждый реализовывал одни и те же теги **по-своему**. Отсюда вечная боль вёрстки: «в одном браузере работает, в другом нет».

Разными бывают шрифты, отступы, поведение форм, видео, скролла. Один и тот же код в Chrome и Safari может выглядеть по-разному.

> **Договорённость курса:** результат смотрим только в **Google Chrome**. Один инструмент у всех — значит, одинаковая картинка, и мы обсуждаем код, а не особенности браузера.

### Web Archive — машина времени

[web.archive.org](https://web.archive.org) хранит копии сайтов с середины 90-х. Вбиваете адрес, выбираете дату на календаре — видите, как сайт выглядел тогда.

Попробуйте: `apple.com` в 1997, `yandex.ru` в 1998, `hse.ru` в 2001.

Отличный источник референсов. И заодно видно: технологии выросли, а базовые теги в коде тех страниц — те же, что мы разберём сегодня.

## 3. Инструменты

Нужны два окна. В одном пишем, в другом смотрим.

### 1. VS Code — редактор кода

**Скачать:** [code.visualstudio.com](https://code.visualstudio.com)

Подсвечивает теги разными цветами, подсказывает варианты, показывает номера строк и ошибки. Бесплатный, ставится за пару минут.

### 2. Google Chrome — браузер

Открывает ваш файл и показывает, что получилось. Плюс инструменты разработчика для отладки (разберём позже).

> Если работаете на аудиторном компьютере — поставьте себе то же самое дома, чтобы делать домашние задания.

### Первый файл за пять шагов

1. Скачать VS Code с [code.visualstudio.com](https://code.visualstudio.com) и установить
2. Открыть редактор и выбрать тему оформления — тёмную или светлую
3. Создать новый файл: `Ctrl + N` (Windows) или `Cmd + N` (macOS)
4. Сохранить как `index.html` — **имя обязательно латиницей, без пробелов**
5. Найти файл на диске и перетащить его на иконку Chrome

**Почему тёмная тема?** Меньше света в глаза на длинных сессиях и лучше видно цветную подсветку кода. Но это вкусовщина — берите то, в чём комфортно.

**Почему латиница в имени файла?** Кириллица и пробелы в именах файлов ломают кодировку и пути. Привыкайте сразу: `index.html`, `narkomfin.html`, `about-me.html`.

**Как найти файл на диске:** правая кнопка по вкладке файла в VS Code → «Reveal in Finder» (macOS) или «Показать в папке» (Windows).

### Горячие клавиши

| Действие | Windows | macOS |
|---|---|---|
| Новый файл | `Ctrl + N` | `Cmd + N` |
| Сохранить | `Ctrl + S` | `Cmd + S` |
| Отменить действие | `Ctrl + Z` | `Cmd + Z` |
| Выделить всё | `Ctrl + A` | `Cmd + A` |
| Копировать / вставить | `Ctrl + C` / `Ctrl + V` | `Cmd + C` / `Cmd + V` |
| Несколько курсоров | `Alt` + клик | `Option` + клик |

Несколько курсоров — самый недооценённый приём: ставите курсор в пяти местах и правите одинаковые теги одновременно.

**Сохраняйтесь после каждого изменения.** `Cmd/Ctrl + S` должно стать рефлексом. Или включите автосохранение: `File → Auto Save`.

## 4. Что такое HTML

**HTML** = **H**yper**T**ext **M**arkup **L**anguage = язык разметки гипертекста.

### Разметка — это не программирование

Вы не даёте команды. Вы **помечаете**: это заголовок, это абзац, это ссылка, это картинка. Браузер читает пометки и рисует страницу.

У HTML есть родственники — языки, которые тоже описывают структуру документа, а не действия: Markdown (заметки, README), LaTeX (научные статьи), PDF.

```markdown
# Заголовок
**жирный текст**
- пункт списка
```

```html
<h1>Заголовок</h1>
<b>жирный текст</b>
<li>пункт списка</li>
```

Одно и то же, разный синтаксис.

### Гипертекст

> **Гипертекст** — текст, из которого можно перейти в другой текст. Связь между ними и есть **гиперссылка**.

- **«Гипер»** — от греческого «сверх», «над». Текст, который вышел за пределы одной страницы.
- **Ссылка** — кликабельный фрагмент, ведущий на другой документ, сайт или место на этой же странице.
- **Сеть** — миллиарды документов, связанных ссылками. Собственно, это и есть World Wide Web.

### Анатомия тега

```html
<a href="https://hse.ru">Сайт Вышки</a>
```

| | |
|---|---|
| `<a>` | **Открывающий тег** — говорит: здесь начинается ссылка |
| `href="..."` | **Атрибут** — дополнительная информация: куда вести |
| `Сайт Вышки` | **Содержимое** — текст, который увидит пользователь |
| `</a>` | **Закрывающий тег** — со слешем. Говорит: ссылка закончилась |

**Парные и одиночные теги.** Большинство тегов парные: `<p>…</p>`. Но есть одиночные — им нечего оборачивать: `<img>`, `<br>`, `<hr>`, `<meta>`.

Самая частая ошибка новичка — забыть закрывающий тег или слеш в нём.

### Скелет любой веб-страницы

```html
<!DOCTYPE html>
<html lang="ru">
  <head>
    ...техническая информация
  </head>
  <body>
    ...то, что видит человек
  </body>
</html>
```

| Тег | Что делает |
|---|---|
| `<!DOCTYPE html>` | Первая строка. Сообщает браузеру: дальше идёт современный HTML |
| `<html>` | Корневой тег. Внутри него живёт вся страница |
| `<head>` | Служебная зона: кодировка, название вкладки, подключение стилей. На странице не видна |
| `<body>` | Тело страницы: весь текст, картинки и ссылки, которые увидит пользователь |

> 💡 В VS Code этот каркас разворачивается автоматически: наберите `!` и нажмите `Tab`. Но структуру всё равно надо понимать.

### Что лежит в `<head>`

```html
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Дом Наркомфина</title>
</head>
```

| Мета-тег | Зачем |
|---|---|
| `charset` | Кодировка UTF-8. Без неё русский текст превратится в кракозябры |
| `viewport` | Говорит мобильным браузерам подстроить ширину под экран телефона |
| `title` | Название вкладки в браузере и заголовок в результатах поиска |

## 5. Теги, из которых собран текст

### Заголовки: `<h1>`–`<h6>`

HTML родился для научных документов — отсюда шесть уровней вложенности.

```html
<h1>Дом Наркомфина</h1>
<h2>История</h2>
<h3>Строительство</h3>
<h4>Реставрация</h4>
```

`<h1>` — самый крупный, `<h6>` — самый мелкий.

> **Важно:** `<h1>` на странице должен быть **один** — это её главный заголовок. Остальные уровни идут по порядку и помогают поисковикам и скринридерам понять структуру.
>
> Размер заголовка — не про внешний вид, а про смысл. Внешний вид потом поменяем через CSS.

### Абзацы: `<p>`

Перенос строки в редакторе браузер **игнорирует**. Несколько пробелов и переносов подряд он схлопывает в один. Абзац нужно обозначить тегом.

```html
<p>Дом Наркомфина построен в 1930 году.</p>

<p>Это памятник <b>конструктивизма</b> и <i>эксперимент</i> в жилье.</p>
```

### Выделение текста

| Тег | Что делает |
|---|---|
| `<b>` | Жирное начертание |
| `<i>` | Курсив |
| `<u>` | Подчёркивание |
| `<br>` | Принудительный перенос строки (одиночный тег) |

Эти теги работают **внутри** абзаца, вокруг отдельных слов.

> 💡 В современной вёрстке вместо `<b>` и `<i>` чаще пишут `<strong>` и `<em>`. Выглядят так же, но сообщают смысл — «важно» и «выделено интонацией». Это принципиально для незрячих пользователей: скринридер меняет интонацию на `<strong>`, но никак не реагирует на `<b>`.

### Списки: `<ul>`, `<ol>`, `<li>`

Список — это всегда два уровня тегов: контейнер и пункты внутри.

```html
<ul>
  <li>Первый пункт</li>
  <li>Второй пункт</li>
</ul>

<ol>
  <li>Шаг первый</li>
  <li>Шаг второй</li>
</ol>
```

- `<ul>` — **u**nordered **l**ist, маркированный список. Порядок пунктов не важен.
- `<ol>` — **o**rdered **l**ist, нумерованный. Номера браузер расставит сам.
- `<li>` — **l**ist **i**tem, отдельный пункт.

> ⚠️ **Частая ошибка:** писать пункты прямо внутри `<ul>`, забыв про `<li>`. Пункт списка — это всегда `<li>…</li>`.

### Ссылка: `<a>`

Главный тег интернета. Без атрибута `href` это просто текст — ссылкой его делает адрес.

```html
<a href="https://www.hse.ru">Сайт Вышки</a>
```

- **Как сделать:** скопируйте адрес из адресной строки браузера и вставьте внутрь кавычек `href`.
- **Куда ведёт:** на другой сайт, на другую вашу страницу или на якорь внутри этой же страницы.
- **Нюанс:** ссылка — строчный элемент, она встраивается в строку текста, а не начинает новую. Чтобы поставить её отдельным блоком, оберните абзацем:

```html
<p><a href="https://www.hse.ru">Сайт Вышки</a></p>
```

### Картинка: `<img>`

Одиночный тег — закрывать не нужно, оборачивать нечего.

```html
<img src="https://site.ru/narkomfin.jpg" alt="Фасад дома Наркомфина">
```

| Атрибут | | |
|---|---|---|
| `src` | *source* | Адрес файла картинки. Правильный адрес заканчивается расширением: `.jpg`, `.png`, `.svg`, `.webp` |
| `alt` | *alternative text* | Текстовое описание. Его читают вслух скринридеры незрячим пользователям и показывает браузер, если картинка не загрузилась |

**Как получить адрес картинки:** правая кнопка мыши по изображению → «Копировать адрес изображения». Не путайте со ссылкой на страницу, где картинка лежит — нужен адрес самого файла.

**Про `alt`:** это не поле для галочки. Описывайте, что на картинке, так, как описали бы человеку по телефону. Хорошая привычка для дизайнера.

### Цитаты: `<blockquote>` и `<cite>`

```html
<blockquote>
  Дом должен быть машиной для жилья.
  <cite>Ле Корбюзье</cite>
</blockquote>
```

- `<blockquote>` — **блочная цитата**: целый фрагмент чужого текста. Браузер по умолчанию делает отступ слева.
- `<cite>` — **источник цитаты**: название книги, автор, работа. Отображается курсивом.

Внешне `<cite>` похож на `<i>` — но `<i>` это просто наклонный шрифт, а `<cite>` сообщает браузеру и поисковику, что перед ним источник.

> **Главная идея HTML:** мы описываем **смысл**, а не оформление. Оформление — задача CSS.

## 6. Чистый код и работа с ошибками

### Отступы ничего не меняют — и меняют всё

Браузеру всё равно, как отформатирован ваш код. Вам и вашему коллеге — нет.

```html
<!-- Работает, но читать больно -->
<ul><li>Раз</li><li>Два</li>
<li>Три</li></ul>
```

```html
<!-- Так же работает, но понятно -->
<ul>
  <li>Раз</li>
  <li>Два</li>
  <li>Три</li>
</ul>
```

- Вложенные теги сдвигаем на два пробела вправо
- Сразу видно, где элемент открылся и где закрылся
- Расширение **Prettier** форматирует код автоматически при сохранении (`Extensions` → найти Prettier → `Install`, затем в настройках включить `Format On Save`)

> Через месяц вы будете читать свой код как чужой. Пишите так, чтобы его было легко понять.

### Ошибки — это нормальная часть работы

Их делают все, включая тех, кто пишет код двадцать лет.

1. **Заметить.** Результат не такой, как ожидали, или редактор подсветил строку.
2. **Найти.** Смотрите на номера строк. Чаще всего это незакрытый тег, пропущенная кавычка или опечатка в имени тега.
3. **Исправить.** `Ctrl/Cmd + Z` отменяет последние действия. Правьте по одному изменению за раз и смотрите результат.
4. **Спросить.** Соседа по парте, куратора, поиск, ChatGPT. Спрашивать не стыдно — стыдно молчать полтора часа.

> **Задача — не скопировать код, а понять, как он устроен.** Пользоваться нейросетью можно и нужно, но вы должны уметь объяснить каждую строчку своего файла. Если не можете — значит, вы её не написали.

### Специфика кода

Код осваивается медленнее, чем дизайн, и только руками. Чем больше вы пишете, тем меньше времени уходит на каждую следующую страницу. Первая займёт час, десятая — десять минут.

## Шпаргалка: теги первого занятия

| Тег | Что делает | Парный? |
|---|---|---|
| `<!DOCTYPE html>` | Объявление типа документа | — |
| `<html>` | Корневой тег страницы | да |
| `<head>` | Служебная информация | да |
| `<body>` | Видимое содержимое | да |
| `<meta charset>` | Кодировка документа | нет |
| `<title>` | Название вкладки | да |
| `<h1>`–`<h6>` | Заголовки шести уровней | да |
| `<p>` | Абзац | да |
| `<b>` / `<strong>` | Жирный текст | да |
| `<i>` / `<em>` | Курсив | да |
| `<u>` | Подчёркивание | да |
| `<br>` | Перенос строки | нет |
| `<ul>` | Маркированный список | да |
| `<ol>` | Нумерованный список | да |
| `<li>` | Пункт списка | да |
| `<a href>` | Ссылка | да |
| `<img src alt>` | Картинка | нет |
| `<blockquote>` | Блочная цитата | да |
| `<cite>` | Источник цитаты | да |

## Готовый шаблон для домашки

```html
<!DOCTYPE html>
<html lang="ru">
  <head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Дом Наркомфина</title>
  </head>
  <body>

    <h1>Дом Наркомфина</h1>

    <p>Первый абзац статьи.</p>

    <h2>История</h2>

    <p>Текст раздела.</p>

    <ul>
      <li>Пункт списка</li>
      <li>Ещё пункт</li>
    </ul>

    <blockquote>
      Текст цитаты.
      <cite>Автор</cite>
    </blockquote>

    <p><a href="https://ru.wikipedia.org">Источник</a></p>

  </body>
</html>
```
