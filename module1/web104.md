# Исходные стили охватывают всю страницу

```css
h1, h2, h3, h4, h5,
p, ul, ol, blockquote {
  width: 700px;
  margin: 0 auto;
}
```

После добавления `nav`:

- список меню получит ширину статьи;
- отступы контента попадут в навигацию;
- одно исправление начнёт ломать другое.

> Селектор по тегу удобен для базовых правил. Компонентам нужны границы влияния.

# Вложенный список находится внутри `li`

**Исходный фрагмент**

```html
<ol>
  <li>Архитектура</li>
  <ol>
    <li>Фасады</li>
  </ol>
</ol>
```

**Корректная структура**

```html
<ol>
  <li>Архитектура
    <ol>
      <li>Фасады</li>
    </ol>
  </li>
</ol>
```

Прямые дети `ul` и `ol` — элементы `li`. Подсписок относится к конкретному пункту.

# `style.css` задаёт порядок слоёв

```css
@import url('./reset.css');
@import url('./fonts.css');
@import url('./layout.css');
@import url('./content.css');
@import url('./sidebar.css');
```

Порядок подключения:

1. сброс стилей;
2. шрифты;
3. общая раскладка;
4. статья;
5. навигация.

> При одинаковой специфичности более позднее правило получает преимущество.

# Два способа подключить несколько файлов

## Учебный вариант

Один `link` подключает `style.css`. Внутри него `@import` показывает порядок и роли файлов.

## Рабочий проект

Несколько `link` или сборщик позволяют управлять загрузкой. Выбор зависит от проекта и целевых браузеров.

> Google Fonts лучше подключать отдельным `link` или хранить шрифты локально по правилам проекта.

# Путь читается от файла, который содержит ссылку

| Путь | Что означает |
|---|---|
| `index.html` | файл рядом |
| `images/photo.jpg` | папка внутри текущей |
| `../images/photo.jpg` | уровень вверх, затем папка `images` |
| `../../layout.css` | два уровня вверх |

> В `@import` путь считается от CSS-файла. В `src` и `href` — от HTML-файла.

# `ul` и `ol` передают разный смысл

## `ul`

Порядок пунктов не меняет смысл.

Примеры: список материалов, набор ссылок.

## `ol`

Порядок важен.

Примеры: этапы процесса, рейтинг, содержание документа.

> CSS может изменить маркер, но не меняет семантику элемента.

---

# `list-style` управляет маркером

```css
.content ul {
  list-style-type: disc;
}

.content ol {
  list-style-type: decimal;
}

.sidebar ul {
  list-style: none;
}
```

Частые значения: `disc`, `circle`, `square`, `decimal`, `lower-alpha`, `none`.

> Сначала выбираем HTML по смыслу, затем оформляем маркер.

---

# Сброс стилей может скрыть маркеры

```css
/* reset.css */
ul, ol {
  list-style: none;
  padding: 0;
}

/* content.css */
.content ul {
  list-style: disc;
  padding-left: 1.5em;
}
```

Современная настройка маркера:

```css
.content li::marker {
  color: #2257C8;
}
```

`::marker` стилизует сам маркер, не создавая отдельный декоративный элемент.

---

# Полоска цитаты начинается с `border-left`

```css
.content blockquote {
  border-left: 4px solid #2257C8;
  padding-left: 24px;
  margin-left: 0;
  color: rgba(0, 0, 0, .65);
}
```

> Архитектура формирует сценарий жизни, а детали делают этот сценарий читаемым.

Для простой линии отдельный псевдоэлемент не нужен.

---

# `::before` создаёт оформляемый псевдоэлемент

```css
.content blockquote::before {
  content: '';
  display: block;
  width: 4px;
  height: 48px;
  background: #2257C8;
}
```

Условия появления:

- селектор совпал;
- `content` не равен `none`;
- `display` и размеры дают видимый box.

> Псевдоэлемент подходит для декора. Смысловой текст остаётся в HTML.

---

# Абсолютное позиционирование ищет positioned-предка

```css
.content blockquote {
  position: relative;
}

.content blockquote::before {
  content: '';
  position: absolute;
  top: 0;
  left: -24px;
}
```

Опорная пара:

- родитель: `position: relative`;
- псевдоэлемент: `position: absolute`.

Без positioned-предка координаты могут считаться от другого контейнера или страницы.

# Sidebar — отдельная навигационная область

```html
<nav class="sidebar" aria-label="Содержание">
  <ul>
    <li><a href="#history">История</a></li>
    <li><a href="#architecture">Архитектура</a></li>
    <li><a href="#restoration">Реставрация</a></li>
  </ul>
</nav>

<article class="content">...</article>
```

- `nav` — навигация;
- `article` — самостоятельный материал.

---

# Emmet разворачивает повторяющуюся структуру

```text
nav.sidebar>ul>li*8>a[href="#"]>{Раздел}
```

Разбор сокращения:

```text
>   вложить
*8  повторить восемь раз
{}  вставить текст
[]  добавить атрибут
```

После разворачивания код нужно прочитать, заменить `href` и проверить вложенность.

---

# Класс `content` ограничивает стили статьи

```css
/* было */
p, ul, ol, blockquote {
  width: 700px;
}

/* стало */
.content p,
.content ul,
.content ol,
.content blockquote {
  width: 700px;
}
```

Результат:

- sidebar сохраняет собственную ширину;
- типографика относится к статье;
- область действия видна в селекторе.

# Комбинаторы описывают отношения элементов

| Селектор | Что выбирает |
|---|---|
| `.sidebar a` | любую ссылку внутри sidebar |
| `.sidebar > ul` | `ul`, который является прямым ребёнком sidebar |
| `.sidebar li:first-child` | первый `li` внутри sidebar |
| `.content h2 + p` | первый `p` сразу после `h2` |

> Чем точнее структура селектора, тем сильнее зависимость CSS от HTML.

# Box model объясняет лишнюю ширину

```css
.sidebar {
  width: 240px;
  padding: 20px;
  border: 1px solid #CCCCCC;
}
```

При `content-box`:

```text
240 + 40 + 2 = 282px
```

`width` задаёт ширину content. `padding` и `border` увеличивают внешний размер.

> Сначала посчитайте box, затем меняйте ширину.

---

# `border-box` сохраняет заданный внешний размер

| `content-box` | `border-box` |
|---|---|
| `width: 240px` | `width: 240px` |
| `padding: 20px` | `padding: 20px` |
| `border: 1px` | `border: 1px` |
| **Внешняя ширина: 282px** | **Внешняя ширина: 240px** |

При `border-box` браузер уменьшает content, чтобы вместить `padding` и `border`.

---

# `calc()` объединяет совместимые значения

```css
.sidebar {
  width: calc(100% - 40px);
}

.hero {
  min-height: calc(100vh - 72px);
}
```

`calc()` полезен, когда нужно:

- смешать проценты и пиксели;
- вычесть известную панель;
- выразить зависимость размеров.

> Для sidebar с внутренним padding сначала попробуйте `border-box`. `calc()` не нужен автоматически.

---

# Единая модель размеров задаётся в reset

```css
*,
*::before,
*::after {
  box-sizing: border-box;
}
```

Псевдоэлементы тоже создают boxes и участвуют в расчёте размеров. Это относится к декоративным полоскам, иконкам и фонам через `::before` и `::after`.

После этого `width` предсказуемо включает content, `padding` и `border`.

---

# Подчёркивание зависит от области ссылки

```css
a {
  color: inherit;
}

.sidebar a {
  text-decoration: none;
}

.content a {
  text-decoration: underline;
  text-underline-offset: .15em;
}
```

В навигации расположение и состояния помогают распознать ссылку. В тексте статьи подчёркивание сохраняет её заметность внутри абзаца.

---

# `opacity` действует на весь результат элемента

```css
.sidebar {
  opacity: .35;
}

.sidebar:hover,
.sidebar:focus-within {
  opacity: 1;
}
```

Прозрачнее станут:

- текст;
- фон;
- иконки и границы;
- все потомки.

> Если нужно ослабить только цвет, используйте цвет с alpha-каналом.

---

# Hover дополняется состоянием клавиатуры

```css
.sidebar:hover,
.sidebar:focus-within {
  opacity: 1;
}

.sidebar a:focus-visible {
  outline: 2px solid #2257C8;
  outline-offset: 3px;
}
```

## Проверка без мыши

Нажимайте `Tab`. Фокус должен быть заметен, а каждая ссылка — достижима и активируема.

Наведение не существует на многих сенсорных устройствах.

# Transition описывает плавное изменение свойства

```css
.sidebar {
  opacity: .35;
  transition: opacity 160ms ease-out;
}

@media (prefers-reduced-motion: reduce) {
  .sidebar {
    transition: none;
  }
}
```

Лучше перечислить конкретное свойство:

```css
transition: opacity 160ms ease-out;
```

Избегайте `transition: all` без необходимости.

# Префиксы отражают историю поддержки браузеров

```css
/* исторический код */
-webkit-border-radius: 5px;
-moz-border-radius: 5px;
border-radius: 5px;

/* современный исходник */
border-radius: 5px;
```

Современный процесс:

1. проверить поддержку свойства;
2. определить целевые браузеры;
3. добавлять префиксы инструментом.

Не копируйте набор префиксов из старой статьи без проверки даты и целей проекта.
